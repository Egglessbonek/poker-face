# Poker Face

**The only opponents who can read your face.**

A No-Limit Hold'em table for friends and AI players. Create a table, share the 4-letter code, and sit down. Every AI at the table also gets your tells: blink rate, gaze, stillness, tension, micro-expressions, and decision timing, read from your webcam in the browser. No microphone, no cursor tracking. Spectators join the **Rail** with the same code and watch the tells live. After the match, the **Reveal** shows exactly which bluffs your face captioned.

## Stack

| Layer | Tech |
| --- | --- |
| App | Next.js 16 (App Router), React 19, Tailwind v4 |
| Camera tells | MediaPipe Face Landmarker (WASM, in-browser, 478 landmarks + 52 blendshapes) |
| Poker | N-player NLHE engine with side pots, `pokersolver` + Monte Carlo equity |
| AI players | Real models via OpenRouter, each playing as itself (no scripted personas): six regulars (Claude, ChatGPT, Grok, Llama, Gemini, DeepSeek) are pinned, the whole catalog is in a dropdown. Equity + tells -> that model -> strict JSON action + table talk in its own voice |
| Voice | ElevenLabs TTS: every AI line is spoken aloud on every client, one signature voice per model vendor (Claude, GPT, Gemini, Grok, Llama, DeepSeek), no two seats at a table share a voice |
| Realtime | Server-Sent Events, in-memory bus, per-viewer filtering (private cards, tell visibility) |
| Rail predictions | Creator-enabled, engine-settled pari-mutuel markets with Phantom-compatible Solana devnet stakes, automatic payouts and post-game results |
| Deploy | Railway (single Node process) |

## How a table works

1. **Host** opens `/table/new`: chairs (2-9), blinds, stacks, hands, turn timer, **the guest list** (any OpenRouter models, duplicates allowed), and **who sees the tells** (AIs and rail by default; humans never see their own during play).
2. **Players** open `/table/<code>`, type a name, and calibrate a required 10s face baseline in the lobby.
3. The host deals. AI turns run on the server; humans get a turn timer that auto-checks/folds.
4. **Spectators** open `/rail/<code>`: every card, every human's live tell HUD, the AIs' stated reads and table talk. If the host enabled predictions, the rail can watch markets wallet-free or stake devnet SOL on the next action, hand winner, finish method, and match winner. After the match, `/rail/<code>/results` summarizes every market and the connected wallet's bets while the treasury sends winning payouts automatically.
5. When the match ends, `/reveal/<code>` grades each human: poker-face score, bluffs caught, biggest leaks, and the moments where a tell changed an AI's action.

During play, SB and BB mark the blind seats (the button is also SB heads-up). Any active player can fold on their own turn, including when checking is free; this is a casual house rule, not the tournament penalty rule for non-standard folds. Timeouts still check when possible. Every player can leave the table; a departed seat folds on its next turn unless already all-in. The host alone can end the match. If the host leaves with another human remaining, hosting passes to that human.

AI speech is generated by a separate stateless request that receives only public action types and a fixed vocabulary of observed behavior. It never receives hole cards, hand evaluations, equity, notebooks or private reasoning. Spoken output passes a conservative filter for card/hand claims, odds, plans, action declarations and coaching before broadcast and again at the TTS endpoint. Rejected or timed-out speech stays silent; speech has a four-second budget within the AI turn's 15-second deadline. Private analysis stays in the server log and the omniscient rail; seated-player streams omit it, and the full log and Reveal open only after the match ends. This is a house game with an open spectator rail, not an anti-collusion tournament platform.

## What the AIs actually see

Nothing is invented. Each human decision ships with a tell vector built in the browser from the webcam, and the AI seats can only cite what is in it (the prompt forbids readings the camera did not report: no pulse, no sweat).

Each human decision produces two evidence lines, and the AIs cite from both.

**On the decision** (the window between being prompted and clicking):

| Signal | Reads as | Why it is in (poker-tells literature) |
| --- | --- | --- |
| Decision timing (fast / slow vs your own norm) | fast bet -> bluff | Timing tells are the strongest class (Elwood, *Reading Poker Tells*) |
| Freeze: head motion far below how still you usually sit while deciding | bluff | Caro; Slepian et al. 2013 on movement smoothness under deception |
| Eyes drop to the bet controls right after a card | strength | Caro's chip glance, the most reliable strength tell, translated to a screen |
| Stared at the flop / turn / river for seconds | weak (bluff if they bet) | Caro: players who miss the flop stare at it; players who hit it look away |
| Looked back at their own cards after a community card | draw (semi-bluff) | Elwood: re-checking hole cards on a draw-heavy board is checking suits |
| Leaned in when a card came | strength | Caro: sudden interest |
| Smile leak (Duchenne) after a card | strength | Ekman; genuine vs social smiles |
| Blink rate vs your baseline, jaw/brow tension | arousal, weak bluff cue | DePaulo et al. 2003 meta-analysis: facial cues are weak alone, so they are capped |

**After a bet** (the five seconds after your own bet or raise), a separate read the AIs see as "after their last bet: …":

| Signal | Reads as | Why it is in |
| --- | --- | --- |
| Froze after betting | bluff | Elwood: bluffers go still after a big bet |
| Looked away and never up at the camera | bluff | Elwood: post-bet gaze avoidance (eye contact, on a screen, is looking up at the camera) |
| Sat back | strength | Elwood: post-bet relaxation |
| Leaned in and held still | bluff | Caro: the frozen lean is the bluffer's posture |
| Blink rate jumped | bluff | Leal & Vrij 2008: liars blink less during the lie and more right after |
| Tension dropped, a genuine smile | strength | Ekman; DePaulo et al. 2003 |

Gaze is coarse on a webcam, so it is used as screen zones relative to your own calibration (board, your cards and the bet controls, up at the camera, away) and as dwell times, never as a point. Posture is the face transform's distance and rotation, so leaning in and sitting back are relative to how you sat during calibration.

Everything is a deviation from **your** baseline: a 10-second calibration in the lobby, then timing adapts to how fast you actually play, and stillness is judged against the median of your own recent decisions (never the calibration), so a naturally still player is not "frozen" on every hand and a freeze cannot fire on your first decision. The AI's math is computed twice, with and without your tells, and the Reveal shows every decision the tells changed.

## Deploy (Railway)

Tables, streams, and turn timers live in one Node process, so the app needs a host that runs a single long-lived server. Serverless platforms (Vercel, Netlify functions) will not work: memory is not shared between invocations and streams are cut off.

1. Railway → New Project → Deploy from GitHub → pick this repo. `railway.json` sets the build, start command, health check (`/api/health`), and a single replica.
2. Variables: `OPENROUTER_API_KEY`, `ELEVENLABS_API_KEY`, the `ELEVENLABS_VOICE_*` ids, and `APP_URL` set to the public URL Railway gives you. To accept rail predictions, also add the funded devnet treasury and RPC variables documented in `.env.example`.
3. Generate a domain under Settings → Networking. Share `https://<domain>/table/<code>` with players and `/rail/<code>` with spectators.

Keep it at one replica. Scaling out would split tables across processes. A redeploy restarts the process and ends every table in progress, so deploy between demos, not during one.

### Checking local AI calls

All seats on a server share `OPENROUTER_API_KEY`; the chosen seat model changes the request's model, not its API key. Separate keys in the OpenRouter dashboard are not automatically rotated. Configure a distinct local key if you want local usage separated from production usage.

Run `npm run check:llm` to verify the key using Next's development environment precedence. Add `-- --completion` for a small billed completion. Restart `npm run dev` after replacing credentials; an existing process can retain an older key. `/api/health` reports `llmStatus` with actual success/failure counts since startup (including speech requests), while `llm` only means a key is configured. The table shows when an AI's latest turn used the built-in strategy after a missing key, failed request, or timeout. No credentials or private completions are included in diagnostics.

### Presage camera measurements

Set `SMARTSPECTRA_API_KEY` and restart the server. Turning on the required camera starts MediaPipe facial analysis and a Presage worker automatically, using the same MediaStream. Camera setup explains that JPEG frames are transmitted to the game server for native processing. Frames are transient and are not saved. Leaving, ending the match or losing the upload stream stops the worker. A missing Presage key or runtime failure does not block poker.

The **Under pressure** panel shows private pulse/breathing estimates directly beneath the camera. It has no timeline or manual retry action. Measurements are available only through the authenticated seat's `/api/table/[code]/vitals` route; they are not added to the public log, rail, AI prompts or bluff-score formula. This deliberately leaves the teammate-owned reveal implementation alone.

The native SDK requires Node 20+ and a supported platform (macOS ARM64, Windows x64, Linux x64/ARM64 with glibc 2.35+). Deploy the repository's `scripts/presage-worker.mjs`, `scripts/presage-metrics.mjs`, `scripts/presage-errors.mjs`, and installed production dependencies alongside `next start`; do not deploy just `.next` without them. `PRESAGE_MAX_SESSIONS` defaults to 2 native workers. Measure CPU/memory and sustained frame delivery before increasing it or enabling a larger public table.

Rates need their full source windows: 12 seconds for pulse, 30 seconds for breathing. We require SDK stability, per-metric validation and configurable confidence cutoffs (`PRESAGE_PULSE_CONFIDENCE` and `PRESAGE_BREATHING_CONFIDENCE`, both default 70, bounded 50–100). These are engineering choices awaiting reference-device validation. Chest-only validation failure blocks breathing independently of pulse. Pulse remains restricted to 40–110 BPM while Presage’s overview and newer model card disagree about the upper limit; breathing is restricted to 5–40/min. Camera guidance matters even with high confidence. The reference is a median of the first 15 usable, overlapping estimates, not a clinical resting baseline. Private history associates public betting events with the measurements without inferring bluffing, stress, or causation.

Face calibration and physiological warm-up are separate. The panel shows a minimum warm-up countdown for each metric, then signal guidance if no usable estimate arrives. Slow workers drop delayed uploads instead of stopping capture; frames older than one second are discarded before native submission. Transient connection failures recover automatically, with at most two reconnects per minute. Authentication/configuration failures and low-confidence signals do not trigger reconnect loops. A transport-only smoke test is not sufficient to validate Presage: the September 13 local API test completed 201 uploads without an error, but the saved face clip received the SDK's “Only one face is allowed” validation and produced zero estimates. Confirm usable pulse and breathing on live cameras before calling the integration verified.

SDK processing failures now restart in a fresh child process, with a new warm-up while retaining completed measurements. Exhausted credits, invalid authentication, and configuration failures show specific messages. Server logs prefixed `[presage] SDK failure` retain the SDK error code, stage, and credential-redacted detail; private diagnostics expose the code and retry policy, never the raw detail. A single malformed JPEG is skipped. Native startup is limited to 30 seconds. Run `CAM=/path/to/consented-face.mjpeg node scripts/e2e-presage.mjs` to exercise calibration, preview handoff, automatic reconnection, and shutdown. Set `PRESAGE_REQUIRE_READINGS=1` to also require usable pulse and breathing; synthetic frames and transport-only passes do not establish measurement quality.

Private measurements are in memory: up to 1,800 samples for the latest camera session, removed two hours after its last frame or on restart. Starting a new camera session resets that session's trace. `DELETE /api/table/[code]/vitals?erase=1` with the seat's Bearer token clears its measurements. Raw frame bodies, secrets and native logs are not exposed by the API.

The lobby and gameplay share a camera panel, keeping the tracking video mounted after calibration. SDK pulse and breathing updates are accumulated independently before once-per-second UI delivery. Their source timestamps are preserved: an update to breathing cannot refresh an old pulse value, and poor-quality updates replace earlier good readings. Both values still expire after three seconds without a fresh estimate.

Presage captures from the same visible video element as facial tracking, including after calibration closes; it no longer depends on video-frame callbacks from a detached video. Every real source frame is eligible for capture, without a second timing filter. Capture stalls are detected, and session status is polled even if no frames arrive. Hidden tabs pause uploads. Signal failures retain specific quality reasons instead of generic lighting advice.


Open **Signal details** under the camera for encoded/submitted FPS, frame size, encode/upload/decode times, source age, skipped frames, and separate pulse/breathing rejection reasons. Coverage counts distinct post-warm-up estimates, not percentage of playing time or accuracy. Cutoffs 50/60/70/80/90 are compared with all other quality checks held fixed; low-quality raw rates are never returned. Change the two environment settings and restart the measurement session to test a policy; no demographic-specific thresholds are used.

Large SDK-reported motion excludes overlapping measurement windows. Visible jaw movement conservatively excludes overlapping breathing windows only; this is an unvalidated artifact heuristic, not a speech detector, and it needs normal-play testing. The stream keeps running through these interruptions. Last valid values appear as **Previous estimate**, with an age, for at most 60 seconds; they never become live values again without a new valid reading. The browser also ages estimates when network responses stop.

Private completed-hand feedback uses distinct, valid measurement windows fully contained in that hand, references only earlier baseline data, and falls back to the player's decision history. It lives in the camera sidebar and does not modify the shared reveal. Decision timing no longer depends on facial calibration: its reference requires three previous decisions on the same street. Interrupted/background turns are excluded, and unusually fast actions are neutral observations rather than automatic bluff evidence.

Run `node scripts/check-presage.mjs` with the local server running to check authenticated API access, synthetic frame delivery to the native SDK, diagnostics, and erasure. This does not measure physiological accuracy. For demo testing, compare each teammate in the same camera/seat/light, then normal talking and moving play; report each person's missing-output rate and coverage separately and compare accepted values with a synchronized independent reference before changing default confidence cutoffs.
